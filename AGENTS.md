# Repository Guidelines

## Project Structure & Module Organization

This repository is a React 19 single-page application built with Vite. Application entry points are `src/main.jsx` and `src/App.jsx`; global styles live in `src/index.css` and `src/App.css`. Feature code is grouped under `src/features/` (currently `learn/`, with `pages/` and reusable `components/`). Lesson content belongs in `src/data/curriculum.js`. Static public files go in `public/`; imported source images and other bundled assets go in `src/assets/`. `dist/` is generated by the production build and should not be edited by hand. There is currently no dedicated test directory or test framework.

## Build, Test, and Development Commands

- `npm install` installs dependencies from the lockfile.
- `npm run dev` starts the Vite development server with hot reload.
- `npm run build` creates the production bundle in `dist/`.
- `npm run preview` serves the production bundle locally for review.
- `npm run lint` runs Oxlint using `.oxlintrc.json`.

Run the lint and build commands before submitting changes. No test script is configured yet; do not assume a test suite exists.

## Coding Style & Naming Conventions

Use JavaScript ES modules and React function components. Follow the existing two-space indentation and single-quote style. Name React components and component files in PascalCase (for example, `LessonCard.jsx`); use camelCase for functions, variables, and data fields. Keep feature-specific UI in its feature directory and shared lesson content in `src/data/`. Preserve the existing CSS custom properties and responsive patterns, and use semantic HTML and accessible labels for interactive elements. Oxlint is the configured linter; fix hook errors and relevant warnings.

## Testing Guidelines

There is no configured automated test framework or coverage threshold. For UI or lesson-flow changes, run `npm run lint` and `npm run build`, then manually review the affected page in the development server at desktop and narrow viewport sizes. If adding tests, first establish a framework and add a documented npm script.

## Commit & Pull Request Guidelines

Recent commits use short, imperative descriptions (for example, “Add warm paper color” and “Build initial Mental Math homepage”). Keep commits focused and describe the user-facing change. Pull requests should include a concise summary, relevant issue link when one exists, verification commands and results, and screenshots for visual changes. Call out curriculum or interaction changes that affect lesson behavior.

## Configuration Notes

Use `package-lock.json` to keep dependency installs reproducible. Do not commit secrets, local environment files, or generated build output. Update curriculum examples in `src/data/curriculum.js` rather than hard-coding lesson text in presentation components.
